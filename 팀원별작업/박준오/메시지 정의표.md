# 예약 시간 연장 메시지 정의표

HTTP/1.1 기반 HTTPS/TCP 443번 포트를 사용한다. JSON 본문은 UTF-8로 인코딩하며 최대 16,384바이트다. 수신 측은 `Content-Length`에 적힌 UTF-8 바이트 수만큼 읽어 본문의 끝을 판단한다.

## RESERVATION_EXTEND_REQ — 예약 시간 연장 요청

HTTP 요청 시작줄: `POST /api/v1/reservations/extend HTTP/1.1`

| 필드명                | 자료형 / 크기                | 설명                                                                     |
| ------------------ | ----------------------- | ---------------------------------------------------------------------- |
| `Host`             | 문자열 / 31바이트             | 요청 헤더. `parking-reservation.example.com`                               |
| `Authorization`    | 문자열 / 최대 2,048바이트       | 요청 헤더. `Bearer `와 로그인 토큰으로 요청 사용자를 인증한다.                               |
| `Content-Type`     | 문자열 / 16바이트             | 요청 헤더. `application/json`                                              |
| `Content-Length`   | 정수값(10진수 문자열) / 최대 5바이트 | 요청 헤더. 아래 JSON 본문의 UTF-8 바이트 수                                         |
| `X-Request-ID`     | UUID 문자열 / 36바이트        | 요청 헤더. 요청과 응답을 연결하는 식별자                                                |
| `Idempotency-Key`  | UUID 문자열 / 36바이트        | 요청 헤더. 같은 연장 시도를 재전송할 때 같은 값을 사용한다.                                    |
| `reservationId`    | UUID 문자열 / 36바이트        | JSON 본문. 연장할 예약의 식별자                                                   |
| `requestedEndTime` | UTC 시각 문자열 / 20바이트      | JSON 본문. 요청하는 새 종료 시각. 형식은 `YYYY-MM-DDTHH:mm:ssZ`이며 현재 종료 시각보다 늦어야 한다. |
### 요청 JSON 예시 — `RESERVATION_EXTEND_REQ`

HTTP 요청: `POST /api/v1/reservations/extend` (요청에는 HTTP 상태 코드가 없음)

```json
{
  "reservationId": "예약 연장 사용자 ID",
  "requestedEndTime": "원하는 연장 시각"
}
```

## RESERVATION_EXTEND_RES — 연장 성공 응답

HTTP 응답 시작줄: `HTTP/1.1 200 OK`

| 필드명                            | 자료형 / 크기                | 설명                                          |
| ------------------------------ | ----------------------- | ------------------------------------------- |
| `Content-Type`                 | 문자열 / 16바이트             | 응답 헤더. `application/json`                   |
| `Content-Length`               | 정수값(10진수 문자열) / 최대 5바이트 | 응답 헤더. 아래 JSON 본문의 UTF-8 바이트 수              |
| `X-Request-ID`                 | UUID 문자열 / 36바이트        | 응답 헤더. 요청에서 받은 값을 그대로 반환한다.                 |
| `resultCode`                   | 정수 / 1바이트               | JSON 본문. 성공 코드 `0`                          |
| `message`                      | 문자열 / 최대 10바이트          | JSON 본문. `SUCCESS`                          |
| `data`                         | JSON 객체 / 본문 전체 제한 이내   | JSON 본문. 확정된 연장 정보                          |
| `data.reservationId`           | UUID 문자열 / 36바이트        | 연장된 예약의 식별자                                 |
| `data.confirmedEndTime`        | UTC 시각 문자열 / 20바이트      | 서버가 확정한 새 종료 시각. 형식은 `YYYY-MM-DDTHH:mm:ssZ` |
| `data.remainingExtensionCount` | 정수 / 1바이트                | 이번 연장 후 남은 가능 횟수. 첫 연장 성공 후 `1`, 두 번째 성공 후 `0` |
### 성공 응답 JSON 예시 — `RESERVATION_EXTEND_RES` (`200 OK`)

HTTP 상태: `200 OK`

```json
{
  "resultCode": 0,
  "message": "SUCCESS",
  "data": {
    "reservationId": "b9315270-1754-47b6-bb47-a1fd3888ff29",
    "confirmedEndTime": "2026-11-16T13:00:00Z",
    "remainingExtensionCount": 1
  }
}
```


## RESERVATION_EXTEND_RES — 연장 실패 응답

HTTP 응답 상태: 실패 원인에 따라 `400 Bad Request`, `401 Unauthorized`, `404 Not Found`, `409 Conflict`, `500 Internal Server Error` 중 하나를 사용한다.

| 필드명              | 자료형 / 크기                | 설명                             |
| ---------------- | ----------------------- | ------------------------------ |
| `Content-Type`   | 문자열 / 16바이트             | 응답 헤더. `application/json`      |
| `Content-Length` | 정수값(10진수 문자열) / 최대 5바이트 | 응답 헤더. 아래 JSON 본문의 UTF-8 바이트 수 |
| `X-Request-ID`   | UUID 문자열 / 36바이트        | 응답 헤더. 요청에서 받은 값을 그대로 반환한다.    |
| `resultCode`     | 정수 / 4바이트               | JSON 본문. 실패 원인을 구분하는 네 자리 코드   |
| `message`        | 문자열 / 최대 32바이트          | JSON 본문. 결과 코드의 영문 이름          |
| `data`           | `null` / 4바이트           | JSON 본문. 실패 시 결과 데이터 없음        |

| HTTP 상태        | `resultCode` | `message`                  | 적용 상황                  |
| -------------- | -----------: | -------------------------- | ---------------------- |
| `409 Conflict` |       `4001` | `EXTENSION_CONFLICT`       | 요청 종료 시각이 다음 예약 시간과 겹침 |
| `409 Conflict` |       `4002` | `EXTENSION_LIMIT_EXCEEDED` | 예약 시간 연장을 2회 모두 사용     |
### 다음 예약과 겹친 경우 

HTTP 상태: `409 Conflict`

```json
{
  "resultCode": 4001,
  "message": "EXTENSION_CONFLICT",
  "data": null
}
```

### 연장 횟수를 초과한 경우 

HTTP 상태: `409 Conflict`

```json
{
  "resultCode": 4002,
  "message": "EXTENSION_LIMIT_EXCEEDED",
  "data": null
}
```
