# 예약 변경·취소 결과 코드표

담당: 최지한 · 대상: `PATCH /api/v1/reservations/{reservationId}`, `POST /api/v1/reservations/{reservationId}/cancel`

서버는 HTTP 상태와 함께 `resultCode`, `message`, `data`를 반환한다. 앱은 HTTP 상태와 숫자 `resultCode`를 함께 검사한다. 응답의 `X-Request-ID`에는 해당 요청에서 받은 값을 넣는다.

## 1. 변경·취소 결과

| HTTP 상태 | `resultCode` | `message` | 발생 상황 | 앱 처리 |
|---|---:|---|---|---|
| `200 OK` | 0 | `SUCCESS` | 예약 변경 또는 취소가 완료됐거나, 동일 작업의 성공 결과를 재전송함 | 변경된 주차면·시각 또는 취소 완료 표시 |
| `400 Bad Request` | 1001 | `INVALID_REQUEST` | 경로·헤더·본문의 필수값 누락, UUID·JSON 구조 오류, 변경 값 없음 | 입력과 요청 형식 수정 후 다시 확인 |
| `400 Bad Request` | 3002 | `INVALID_RESERVATION_TIME` | 시간 문자열 형식 오류 또는 변경 결과가 현재 시각과 같거나 그 전에 시작하거나 종료가 시작보다 늦지 않음 | 시간 값을 수정하고 다시 확인 |
| `401 Unauthorized` | 1004 | `INVALID_TOKEN` | 토큰 누락·만료·검증 실패 | 재인증. 같은 사용자로 원래 작업을 재전송할 때 요청 키 유지 |
| `403 Forbidden` | 3011 | `RESERVATION_FORBIDDEN` | 예약이 현재 사용자 소유가 아님 | 접근 불가 안내 및 본인 예약 목록 확인 |
| `404 Not Found` | 3001 | `SPACE_NOT_FOUND` | 변경할 주차면 ID가 존재하지 않음 | 주차 현황 재조회 |
| `404 Not Found` | 3010 | `RESERVATION_NOT_FOUND` | 예약 ID에 해당하는 예약이 없음 | 예약 목록 갱신 |
| `409 Conflict` | 3003 | `SPACE_ALREADY_RESERVED` | 변경할 주차면의 시간대가 다른 유효 예약과 겹침 | 기존 예약 유지 안내, 최신 현황을 조회해 새 자리·시간 선택 |
| `409 Conflict` | 3004 | `IDEMPOTENCY_KEY_CONFLICT` | 같은 사용자와 작업 키로 다른 메서드·경로·본문을 보냄 | 원래 작업이 불확실하면 최신 예약 확인. 사용자 확인을 거친 별도 작업에만 새 키 사용 |
| `409 Conflict` | 3005 | `IDEMPOTENCY_REQUEST_IN_PROGRESS` | 같은 작업이 아직 처리 중 | 잠시 후 같은 본문·키로 재전송, 새 `X-Request-ID` 사용 |
| `409 Conflict` | 3020 | `RESERVATION_STATE_CONFLICT` | 이미 시작했거나 만료·취소된 예약에 신규 변경·취소를 요청함 | 최신 상태 조회 후 변경·취소 불가 안내 |
| `409 Conflict` | 3021 | `RESERVATION_CHANGED` | 변경·연장 등의 영향으로 현재 주차면·시작·종료 시각이 `expected`와 다름 | 최신 예약 조회 후 사용자가 재확인하면 최신 `expected`와 새 키로 전송 |
| `409 Conflict` | 3022 | `USE_RESERVATION_EXTEND` | 예약 변경으로 기존 사용 시간보다 긴 구간을 요청함 | 같은 주차면의 종료 시각 연장이 목적이면 전용 연장 요청으로 안내 |
| `500 Internal Server Error` | 9001 | `INTERNAL_SERVER_ERROR` | 서버 내부 처리 실패 | 결과가 불확실하면 잠시 뒤 같은 작업 키로 재시도. 계속 확인되지 않으면 최신 예약 조회 |

`1001`, `1004`, `3001`~`3005`, `9001`은 인증·예약 생성 명세의 의미를 따른다. `3010`, `3011`은 예약 조회의 잠정 번호를 재사용한다. `3020`~`3022`는 변경·취소 제안 번호다. 메인 서버 주차 현황 문서에도 `1001`이 다른 의미로 쓰여 있어, 팀 통합 시 공통·인증 코드 매핑을 맞춰야 한다.

## 2. 실패 응답 예시

### 연장으로 변경 또는 취소 요청의 확인 값이 달라진 경우 — HTTP 409

```json
{
  "resultCode": 3021,
  "message": "RESERVATION_CHANGED",
  "data": null
}
```

### 동일 작업이 처리 중인 경우 — HTTP 409

```json
{
  "resultCode": 3005,
  "message": "IDEMPOTENCY_REQUEST_IN_PROGRESS",
  "data": null
}
```

## 3. A-5 연장 API에서 받는 관련 코드

| HTTP 상태 | `resultCode` | `message` | 발생 상황 및 앱 처리 |
|---|---:|---|---|
| `409 Conflict` | 4001 | `EXTENSION_CONFLICT` | 요청이 다음 예약과 겹침. 기존 종료 시각을 유지하고 최신 예약·현황을 조회 |
| `409 Conflict` | 4002 | `EXTENSION_LIMIT_EXCEEDED` | 연장 2회 사용 완료. 남은 횟수 0을 표시 |

두 코드는 A-5 연장 명세에서 정의한다. 변경·취소 요청에서 응답 유실이 발생하면 HTTP 오류가 도착한 경우와 구분한다. 앱은 같은 키·본문으로 먼저 결과를 복구하고, 보존 기간이 지났거나 결과를 확인할 수 없으면 예약을 조회한 뒤 사용자의 확인을 받는다.
