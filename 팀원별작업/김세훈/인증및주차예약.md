A조 네트워크 프로토콜 설계
담당: 김세훈  
기능: 인증(LOGIN) + 예약 생성(RESERVATION_CREATE)

통신: HTTPS (TCP 443)  
데이터: JSON (UTF-8)  
본문 최대 크기: 16KB

공통 규칙

- Base Path: `/api/v1`
- Content-Type: `application/json`
- Content-Length: JSON 본문의 UTF-8 바이트 수
- 시간 형식: `YYYY-MM-DDTHH:mm:ssZ` (UTC)
- X-Request-ID: 요청할 때 보낸 값을 성공/실패 상관없이 응답에도 그대로 넣음
- 인증: `Authorization: Bearer {토큰}`
- 중복 방지: `Idempotency-Key` (예약 생성 시 사용)

응답 기본 형태:

성공
json
{
  "resultCode": 0,
  "message": "SUCCESS",
  "data": { ... }
}

실패
JSON{
  "resultCode": 숫자,
  "message": "영문코드",
  "data": null
}

resultCode 대역:
1000번대 → 인증
3000번대 → 예약
9000번대 → 서버 에러

1. 로그인

요청POST /api/v1/auth/login

헤더:
Host
Content-Type: application/json
Content-Length
X-Request-ID


본문:
JSON
{
  "userId": "user123",
  "password": "password123"
}


성공 응답 (200 OK)
JSON
{
  "resultCode": 0,
  "message": "SUCCESS",
  "data": {
    "accessToken": "발급된토큰",
    "tokenType": "Bearer",
    "expiresAt": "2026-11-23T14:00:00Z"
  }
}

실패 응답
| 상태코드 | resultCode | message | 상황 |
| --- | --- | --- | --- |
| 400 | 1001 | INVALID_REQUEST | 필수값 누락 또는 형식 오류 |
| 401 | 1002 | INVALID_CREDENTIALS | 아이디 또는 비밀번호 오류 |
| 403 | 1003 | ACCOUNT_DISABLED | 계정 비활성화 |
| 500 | 9001 | INTERNAL_SERVER_ERROR | 서버 내부 오류 |

2. 예약 생성

요청POST /api/v1/reservations

헤더:
Host
Authorization: Bearer {토큰}
Content-Type: application/json
Content-Length
X-Request-ID
Idempotency-Key 

본문:
JSON
{
  "spaceId": "PARK-A-101",
  "startTime": "2026-11-23T10:00:00Z",
  "endTime": "2026-11-23T12:00:00Z"
}

성공 응답 (201 Created)
JSON
{
  "resultCode": 0,
  "message": "SUCCESS",
  "data": {
    "reservationId": "b9315270-1754-47b6-bb47-a1fd3888ff29",
    "spaceId": "PARK-A-101",
    "startTime": "2026-11-23T10:00:00Z",
    "endTime": "2026-11-23T12:00:00Z"
  }
}

실패 응답
| 상태코드 | resultCode | message | 상황 |
| --- | --- | --- | --- |
| 400 | 3002 | INVALID_RESERVATION_TIME | 시작 시간이 종료 시간보다 늦거나 같음 / 이미 지난 시간으로 요청 / 시간 형식 오류 |
| 401 | 1004 | INVALID_TOKEN | 토큰이 유효하지 않음 |
| 404 | 3001 | SPACE_NOT_FOUND | 존재하지 않는 주차면 |
| 409 | 3003 | SPACE_ALREADY_RESERVED | 이미 예약된 자리거나 시간 충돌 |
| 409 | 3004 | IDEMPOTENCY_KEY_CONFLICT | 같은 키로 다른 내용 요청 |
| 409 | 3005 | IDEMPOTENCY_REQUEST_IN_PROGRESS | 같은 키 요청이 아직 처리 중 |
| 500 | 9001 | INTERNAL_SERVER_ERROR | 서버 내부 오류 |

처리 흐름
로그인
앱이 아이디/비밀번호 전송
서버가 확인 후 토큰 발급하거나 에러 반환
앱은 받은 토큰을 저장해서 이후 요청에 사용

예약 생성
앱이 Idempotency-Key를 생성해서 같이 보냄
서버가 토큰 검증 → Idempotency-Key 확인 → 자리/시간 충돌 검사
가능하면 예약 생성 후 201 반환
충돌이면 409 + 해당 코드 반환 → 앱은 사용자에게 알리고 현황 다시 조회
응답이 늦어서 재전송할 때는 같은 Idempotency-Key를 유지

중복 요청 / 동시 예약 처리
Idempotency-Key
같은 키 + 같은 내용 → 이전 처리 결과 그대로 반환
같은 키 + 다른 내용 → 409 + IDEMPOTENCY_KEY_CONFLICT
같은 키 요청이 아직 처리 중 → 409 + IDEMPOTENCY_REQUEST_IN_PROGRESS

동시 예약
여러 요청이 동시에 들어와도 단순 조회 후 등록이 아니라
DB 트랜잭션과 시간 중복 방지 제약조건을 사용해서 원자적으로 처리함.
먼저 성공한 요청만 예약되고, 나머지는 SPACE_ALREADY_RESERVED로 거절함.
